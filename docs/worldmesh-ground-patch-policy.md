# 地面面片强制政策（Ground Patch Mandate）

> 创建日期：2026-11-03
>
> 状态：**已定稿（架构约束，不是优化建议）**
>
> 适用：`Airia/lulilo/terrain/`、`movement/`、`entities/`、`combat/`、`simulation/`、`navmesh/`、`render/`
>
> 上位文档：`docs/worldmesh-3d-surface-design.md`（本文件是其 §1 结论的**执行条款**）
>
> **一句话**：地面必须作为显式 `WorldPatch` 存在于 `WorldMesh`。减少面片数只能靠「合并面片 / 给面片加顶点」，永远不能靠「取消地面面片、改为查高度场」。

---

## 0. 红线（先看这个）

| # | 禁止 | 说明 |
|---|------|------|
| 红线 1 | 逻辑 `WorldMesh` 里没有地面 `MAT_TERRAIN` 顶面面片 | 地面 patch 是单位状态机、悬挂、面片局部性判定的锚点 |
| 红线 2 | 运行时用 `Heightfield.surface_z()` / `continuous_ground` 网格给单位定 z | 它们只是**存储**与**渲染输入**，不是世界模型查询入口 |
| 红线 3 | 因为「面片太多」就跳过地面 patch 的生成 | 面片多要合并，不是删除；删除等于拆掉 3D 世界模型的底座 |

违反任一条的方案，无论性能数字多漂亮，**直接否决**，不需要进一步讨论。

## 1. 这份文件要挡住的提案（B 方案）

### 1.1 提案原文（历史上真实出现过）

> 默认地图 400×400 格，平地也要生成 **160,000 个地面面片**，构建 21–26 s，
> 首次 `locate_patch` 还要再花 15 s 建 160k 个 shapely Polygon + STRtree，内存几十 MB。
> 反正地面 z 就是 `continuous_ground` 那张 (400,400) 网格，
> 不如 **地面根本不进 patch 集合**，`WorldMesh` 只留桥/建筑/隧道；
> 单位贴地时直接读网格（或回退 `Heightfield.surface_z`），缺 patch 时兜底一下就行。

这就是 **B 方案**，本文件存在的唯一目的就是让它不再被提出来。

### 1.2 为什么它看起来很有道理

- 它抓住了一个真实的浪费：平地逐格面片确实是纯冗余（详见 §2 的代价基线）。
- 它有一个现成的、看起来「等价」的数据源：`continuous_ground` 网格。
- 它能把面片数从 160,000 变成 0，收益极其显眼，评审时非常容易被接受。

**但它的收益是「删掉数据」，代价是「删掉语义」。** 下面逐条拆。

### 1.3 正确解法（同一问题的合法路径）

> 「160k 平地 patch 太浪费」→ 合并共面/低曲率面片（A），平地图收敛到 O(1) 个 patch。
> 不是把地面从世界模型里拿掉。压缩的是**面片数量**，不是**面片存在性**。

## 2. 代价基线（为什么这个问题值得解决）

2026-11-03 在本仓库默认演示地图（400×400 格 × 37.5 m，`amplitude=0` 全平，15 km 见方）实测：

| 项目 | 数值 |
|------|------|
| 逻辑 `WorldMesh` 面片 | 160,000（全部 `FACE_TOP` / `MAT_TERRAIN`，逐格：`dual_contour.py:268-299`） |
| 构建耗时 | 21–26 s |
| 首次 `locate_patch`（建 160k shapely Polygon + STRtree） | +15 s |
| 面片内存 | ≈ 44 MB（对象 7.7 + `ndarray` 头 28 + 顶点 7.7）+ 索引 12.6 MB |
| 渲染地面网格 | 641,601 顶点 / 1,280,000 三角形（`SUBDIV=2` 硬细分） |
| 渲染结构面片 | 0 |

结论：**加载期确实亏**（一次 40 s 量级、几十 MB），**但这笔账要通过合并面片来还**。注意渲染层本来就不消费这些地面 patch（`include_ground=False`，`Airia/lulilo/terrain/map.py:112-128`），所以它们只影响加载与内存，不影响帧率。

> 顺带纠正一个被写进文档的性能假设：`docs/worldmesh-3d-surface-design.md:573` 写「面片数 50~200」，
> 在 15 km 网格下早就不成立了。**要修的是这个假设，不是世界模型。**

## 3. 术语与职责边界（90% 的争论来自范畴错误）

| 名字 | 是什么 | 不是什么 | 合法消费者 |
|------|--------|----------|-----------|
| `Heightfield`（列式 span） | 体素存储：每列升序实心段；碰撞粗筛、遮蔽、生成期 | **不是表面**，没有面片身份、没有法线、没有材质 | `detection/los`、生成期、粗筛兜底 |
| `continuous_ground` (H,W) | 生成期平滑高度场：给地面 patch 顶点算 z；给渲染网格算顶点 | **不是世界模型**：没有洞、没有多层、没有法线、没有身份 | `terrain/` 生成与**渲染**网格构建 |
| `WorldMesh` / `WorldPatch` | **运行时唯一世界真相**：几何 + 法线 + 材质 + 面朝向 + 可行走性 + `patch_id` | 不是缓存、不是渲染附属品 | `movement`、`entities`、`navmesh`、`combat`、`render` |
| `NavGraph`（三角形） | 寻路搜索空间，由面片派生 | 不承担 z 采样 | `movement/nav`、`pathfinding` |

三条容易被混淆的事实：

1. `Heightfield` 是**存储格式**，`WorldMesh` 是**世界模型**；前者可以粗（`ch=1m` 量化），后者必须精确（连续场平滑）。
2. `continuous_ground` 只在**加载期**被消费两次：生成地面 patch 顶点 z、生成渲染三角网格。它**没有**「运行时查询源」这个身份。
3. 渲染地面网格是 `continuous_ground` 的**一次性三角化产物**（`WorldMeshRenderer`），消费完就交给 GPU，**不得回流**给物理/导航。

## 4. 为什么 B 必须被否决（十条）

### 4.1 世界模型唯一性

`WorldMesh` 是 render / nav / collision **三位一体**的世界模型（`Airia/lulilo/terrain/surface_mesh.py:1-11`、`docs/worldmesh-3d-surface-design.md:21-32`）。
「地面不在 WorldMesh 里」等于宣布：世界模型有洞，地面是二等公民。之后每个消费者都要知道「地面是特殊的」，特殊分支会扩散到每一条查询路径。

### 4.2 同 (x,y) 多表面裁决失效

同一 `(x,y)` 可能同时有：地面、桥面、桥底、隧道顶/底、建筑楼板。`locate_patch(..., hint_z=)` 的工作方式是**在候选面片集合里**比较各面片的 `ray_plane_z` 与 `hint_z` 的接近程度（`Airia/lulilo/terrain/world_mesh.py:244-292`）。
地面一旦不在集合里，「桥下单位」就永远找不到脚下那块地面面片：

- 桥下装甲的 `hint_z` 指向地面 → 候选集合里只有桥面 → 被强行抬到桥面上；
- 或者反过来，车辆过桥时掉进「地面兜底」分支 → 从桥面瞬移到桥下。

同一个 z 网格**只有一个 z 值**，物理上就表达不了这种重叠。这不是实现细节，是数据结构的能力边界。

### 4.3 面片身份契约（`mesh_id`）

`ArmorPool.mesh_id` 存的是**面片 ID**（`Airia/lulilo/entities/pools.py:145-151`），`contact_mesh_id` 是四个悬挂触点各自的面片（`:236`）。

`integrate.py` 的移动热路径靠它做**局部性判定**：每 tick 先问「还在当前面片里吗」——命中率 99%+，直接双线性取 z；越界才回落 `locate_patch`（`Airia/lulilo/movement/integrate.py:333-345`）。

地面 patch 消失 → `mesh_id` 没有合法值 → 这套 O(1) 判定整体失效，每帧每车都要退化成「全局定位 + 兜底分支」。**B 方案不是省一次查询，是把每次查询都变成最坏情况。**

### 4.4 面片携带的不只是 z

`WorldPatch` 带 `mat` / `face` / `normal` / `area` / `walkable`。消费者依赖它们做：

- 可行走筛选（`_mark_walkable`、`locate_walkable`）；
- 材质着色、桥/建筑/隧道的渲染分色；
- 悬挂/贴地法线（`z_at` / 梯度法线，`Airia/lulilo/terrain/world_mesh.py:170-190`）；
- 桥面/地面在桥头处的邻接与寻路 portal。

z 网格只有 z。把地面踢出面片集合，等于把这些语义逐个复制成「地面特判」。

### 4.5 破坏与局部重建

`Heightfield.remove_span()` 炸桥/炸地面之后，靠「面片集合 → 脏块 → 局部重建」维持一致（`Airia/lulilo/terrain/map.py:102-110`）。
隐式网格没有「哪一块面片变了」的概念，重建只能整图重算，`patch_id` 也不再稳定——所有持有 `mesh_id` 的单位、孪生、AI 记忆全部要重新绑定。

### 4.6 双口径分叉有前科

2026-08-10~12 期间「渲染用平滑网格、逻辑用量化层」就制造过 1 m 台阶与规律斜纹，最后靠「渲染和逻辑共用同一份连续场 + 面片双线性」才统一（见 `Airia/lulilo/terrain/surface.py:1-11`、`docs/worldmesh-3d-surface-design.md:542`）。
B 方案会把同一个分叉重新引回来，只是这次分叉发生在「地面 vs 其他表面」之间，更隐蔽、更难测。

### 4.7 复杂度是转移，不是消除

B 方案的查询变成：

```
pid = locate_patch(x, y, hint_z)          # 只剩结构
if pid < 0:                                # 地面兜底
    z = continuous_ground 双线性(x, y)      # 或 heightfield.surface_z
```

看起来只多一个分支，实际每个分支都要维护：多表面裁决（§4.2）、边界一致性（§4.8）、重建失效（§4.5）、测试基线（§4.9）。
而这段代码位于**每 tick × 每个单位 × 每个触点**的热路径上，错误会被放大 2048×4 倍。

### 4.8 边界立刻出错

桥头、隧道口、建筑贴地处，地面与结构在几何上接缝。「地面走网格、结构走面片」意味着接缝两侧的采样公式不同（一个双线性、一个平面求交），**接缝必然出现 z 跳变或悬空**。这不是调参能解决的，是两套几何表示的固有误差。

### 4.9 可测性归零

面片是离散对象，测试可以断言「数量 / 材质 / 可行走 / 定位结果 / 双线性 z」（如 `tests/test_dual_contour.py:120-128`）。
隐式网格只能近似断言，回归护栏失去抓手——而这类几何重构恰恰是最容易悄悄错的地方。

### 4.10 与演进方向冲突

Phase 9（15 km→400 km 大地图）要的是流式/分块，不是「删掉表面」；斜面、悬挑、多层、弹坑、可破坏建筑，全都要求**面片是几何原语**。
把地面锁死在 (H,W) 网格上，等于把世界模型永久钉在 2.5D——`docs/worldmesh-3d-surface-design.md:32` 的结论会被悄悄推翻。

## 5. 允许的减面手段（正向清单）

减少面片数 = **让每个面片覆盖更大区域 / 携带更多顶点**，而不是让地面消失。

| 手段 | 说明 | 前提 |
|------|------|------|
| **共面/误差界合并** | 2D greedy merge，仅当矩形四角 z 能在 ±ε 内复原组内所有格角 z；平地图 → 1 个 patch | 合并后 `z_at()` 误差 ≤ ε（建议 ε ≤ 5 cm） |
| **面片多边形化 / TIN** | 矩形 → 带内部顶点的多边形（顶点仍由连续场采样），面片数降、内部起伏保留 | 查询仍返回 `patch_id`，z 仍由**面片几何**求交 |
| **区块 patch（block patch）** | 一个 patch 覆盖 N×M 格，但**自带全部顶点** | 同上；禁止「区块只存索引、顶点去网格取」 |
| **结构层合并** | 现状：桥/建筑/隧道顶底 2D 合并、侧面沿墙一维合并（`dual_contour.py` 的 `_emit_merged` / `_build_sides`，约 `:305-405`） | 已实施 |
| **渲染侧优化** | 自适应细分（平地少三角）、分块视锥剔除、LOD | 属渲染优化，不改变世界模型 |

**判据只有一句：查询入口不变——`locate_patch` 返回 `patch_id`，z 由该 patch 的几何求出。**

## 6. 反模式清单（看到就退回）

### 6.1 代码

```python
# ❌ 禁止：缺 patch 就查高度场
pid = world_mesh.locate_patch(x, y, hint_z=z)
if pid < 0:
    return heightfield.surface_z(gx, gy, 0)          # ← B 方案

# ❌ 禁止：movement / entities / combat / simulation 读连续场
from ...terrain.map import terrain
z = terrain.continuous_ground[gy, gx]                # ← B 方案

# ❌ 禁止：逻辑 WorldMesh 跳过地面
DualContourBuilder(hf, include_ground=False)         # 只允许 render_world_mesh 用

# ❌ 禁止：把「贴地」实现成「没有面片时的默认值」
if pid < 0:
    armor_z[i] = 0.0                                 # ← 静默错误，比崩溃更糟
```

### 6.2 注释与命名

- ❌「地面 patch 是纯负担」——这句话只在**渲染**语境成立，必须写清「仅渲染」，否则下一个 Agent 会照着它推广到逻辑层。
- ❌ `include_ground` 出现在非渲染构建器调用里。
- ❌ 变量名 `ground_z_fallback` / `no_patch_default`。
- ❌ 提案标题「把地面从 WorldMesh 拿掉 / 地面不入面片」。

### 6.3 提案措辞

- 「反正网格有 z，查询直接读网格就行」→ 属于 B。
- 「只在没有结构的地方走网格」→ 属于 B（边界立刻出错，§4.8）。
- 「先把地面 patch 生成成懒加载，用到再建」→ **不是 B**，但会破坏 `mesh_id` 稳定性与破坏重建语义，需单独立项评估。

## 7. 判定问答（预演未来的提案）

**Q1：160k 平地 patch 明明全是冗余，为什么不能直接读网格？**
A：冗余的是「逐格」，不是「面片」。合并共面格 → 相同查询语义、1 个面片。删面片则同时删掉 `mesh_id`、多表面裁决、材质/法线/可行走性。

**Q2：渲染不就在读 `continuous_ground` 吗？物理为什么不行？**
A：渲染把它三角化成一次性 GPU 产物，消费完即弃，没有跨帧身份、不需要与结构做集合裁决；物理需要跨帧稳定的 `patch_id`、需要在地面/桥面/隧道之间裁决、需要在破坏后重建。需求不同，数据源不能共享。

**Q3：那在没有结构的地方用网格兜底，总可以吧？**
A：这就是 B。「有没有结构」是运行时状态（桥被炸掉就没了），兜底路径会在破坏后立刻激活，且接缝两侧几何表示不同 → z 跳变。

**Q4：如果我只是把网格「包」成一个 patch（block patch 引用网格）呢？**
A：允许，**条件是**：patch 自带顶点与几何，`locate_patch` 返回它的 id，`z_at` 由 patch 顶点求交，查询期不跳转到网格。若只是拿 patch 当「网格区块的索引」，查询时再去读网格 → 仍属 B。

**Q5：面片数真的降不下来怎么办？**
A：按 §5 走：误差界合并 → 多边形化 → 区块 patch。另外先确认瓶颈是不是真的在面片数（当前 40 s 里有一半是 shapely 索引，属于可优化项，不在本政策范围）。

**Q6：如果哪天高度场查询确实更合适（比如纯飞行器/远景 LOD）？**
A：那是**粗筛/表现层**用途，显式标注 `# coarse only`，不得进入单位状态机，不得写回 `mesh_id`。

## 8. 执行与验收

### 8.1 评审 checklist（任何触及地形的 PR 必答）

1. 改动后，逻辑 `WorldMesh` 是否仍对每个可行走格提供 `MAT_TERRAIN` 顶面面片？
2. 是否有任何运行时查询路径读取 `continuous_ground` / `Heightfield.surface_z` 来决定单位 z？
3. 新增的「减面」改动，是否保持 `locate_patch → patch_id → 几何求交` 这条链不变？
4. 平地图基线是否仍收敛（不得回退成逐格）？

### 8.2 建议护栏测试（待 A 方案落地后补齐）

- `tests/test_worldmesh_ground_mandate.py`
  - 平地图 400×400：地面 `FACE_TOP` patch 数 ≤ 8 且 ≥ 1；`locate_patch` 在任意点返回地面面片；`z_at` 误差 ≤ 1e-3。
  - 多表面地图（桥）：桥下与桥面都能定位到各自面片（`hint_z` 裁决）。
  - 破坏后重建：`remove_span` → 面片集合更新且 `patch_id` 可重新绑定。
- 导入护栏：`movement/`、`entities/`、`combat/`、`simulation/` 不得 import `continuous_ground`（静态检查或单元测试断言）。

### 8.3 性能验收（A 方案目标）

| 指标 | 目标 |
|------|------|
| 平地图地面 patch 数 | O(1)（≤ 8） |
| 平地图 WorldMesh 构建 | < 0.5 s |
| 起伏地图 | 面片数随曲率增长，不随格数线性增长 |
| `locate_patch` 语义 | 不变（返回 `patch_id`） |

## 11. 速查（给未来的自己 / 下一个 Agent）

```
地面 = 显式 WorldPatch（MAT_TERRAIN + FACE_TOP），必须存在于逻辑 WorldMesh。
面片多 → 合并（共面/误差界/多边形化/区块 patch）。
面片少 → 也不许改读网格。
查询链永远是：locate_patch(x,y,hint_z) → patch_id → patch.z_at(x,y)。
continuous_ground 只喂两种东西：patch 顶点 z（加载期）、渲染三角网格（一次性）。
```
