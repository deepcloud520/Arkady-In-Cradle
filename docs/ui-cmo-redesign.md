## 零、问题的重新定义

初版讨论把问题拆成「战场信息层缺什么」和「侧栏该放哪」，但对照 CMO 后结论要修正：

| 初版假设 | 修正后 |
|---|---|
| 侧栏要在「详情常驻 / 双模布局 / 浮动卡」之间选一个 | **都不对**。CMO 的侧栏不是分页的，是**可折叠分组堆叠**（accordion）。问题不在「放哪」，在「内部不该是 Tab」 |
| 缺「指挥 UI」，得先做框选 + 右键菜单 | 优先级反了。CMO 的指挥入口**主要在右侧面板的按钮**（油门档位、传感器开关），右键菜单是补充 |
| HUD 只要加血条/朝向就够 | 符号层需要**独立于 3D 模型的语义层**，且必须做 LOD，否则 2048 单位必糊屏 |

核心判断：**现有 `WorldAdapter` 已经提供了几乎所有需要的数据**（`armor_yaw` / `armor_health` / `armor_order` / `formation_*` / `armor_speed` / `box_half` / `box_part` / `box_armor_mm`），瓶颈完全在视觉语言与控件组织，**不需要动机/后端数据结构**。

## 一、CMO 界面解剖（截图为据）

### 1.1 五区结构

```
┌─ 菜单栏 ────────────────────────────────────────────────────────┐
├─ 动作栏（图标大按钮，未选单位时置灰）──────────────────────────┤
│  Auto Engage │ Manual Engage │ Plot Course │ Throttle & Alt │   │
│  Formation Editor │ Magazines │ Weapons │ Sensors │ Damage │…   │
├─ 时间行：Zulu / Local / 倒计时 / Camera Alt ────────────────────┤
│                                                                 │
│   地图（2D 俯视）                          ┌─ UNIT STATUS ────┐ │
│   · 单位剪影 + 朝向线 + 速度矢量           │ ▸ 缩略图          │ │
│   · 名称 / 航向 / 速度 三行标签            │ ▸ 基本            │ │
│   · 橙色射程圈                             │ ▸ 损伤 / 系统     │ │
│   · 航路点 + 折线                          │ ▸ UNIT ALT/SPEED  │ │
│   · 比例尺（右下）                         │ ▸ UNIT FUEL       │ │
│                                            │ ▸ UNIT EMCOM      │ │
│                                            │ ▸ DOCTRINE        │ │
│                                            └──────────────────┘ │
├─ Message Log ──────────────┬─ 光标坐标/地形 ─┬─ 比例尺 ────────┤
├─ 时间压缩：Group View │ 15 sec │ 1 min │ 5 min │ 15 min ───────┤
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 三条可迁移的设计原则

1. **折叠分组 > 分页**：`Damage / Fuel / EMCON / Doctrine` 同时可见，玩家不需要来回切 Tab。分组标题可折叠，状态可记忆。
2. **状态 + 命令同居**：`UNIT ALT/SPEED` 分组里既显示当前档位（`Flank`），又有 `Stop / Creep / Cruise / Full / Flank` 五个按钮直接下命令。**读和写在同一屏块内**。
3. **地图是语义层，不是写实层**：CMO 单位图标是**俯视剪影 + 朝向线 + 速度矢量**，属于"地图符号"而非"3D 渲染"。名称/航向/速度是**三行挂载标签**，不是模型贴花。

### 1.3 必须放弃的 CMO 特征

| CMO 特征 | 为什么不照搬 |
|---|---|
| 2D 俯视地图 | 我们是 3D 透视（Phase 1 已定，`OrbitCamera`）。取信息组织，不取投影方式 |
| 全屏工具栏 13 个图标按钮 | 当前项目尚无对应功能（Aircraft Ops / Boat Ops / Doctrine），**先做动作栏骨架，按钮按功能可用性逐个点亮**，不做空壳 |
| `Mission Editor` / `Ref. Points` | 属 Phase 6+ 范围，本设计不涉及 |

## 三、A 线：侧栏折叠分组

### 3.1 目标结构

右侧栏不再是一个 `QTabWidget`，而是「**常驻信息区 + 可折叠分组堆叠**」：

```
┌─ UNIT STATUS ────────────────────────┐
│ ┌─────┐  M1A2 #03                    │  ← 固定头部（不随滚动）
│ │缩略图│  北约 · 坦克 · 战斗中         │
│ └─────┘  [ 已选中 ]                  │
├──────────────────────────────────────┤
│ ▾ 基本状态                            │  ← 可折叠分组
│   阵营    北约        航向   032°      │
│   速度    12 m/s      高度   4 m       │
│   位置    (124.3, 88.1)               │
├──────────────────────────────────────┤
│ ▾ 损伤与系统                          │
│   结构  ████████░░  62%               │
│   车体  ██████████  600mm  完好        │
│   炮塔  ██████░░░░  400mm  完好        │
│   引擎  ░░░░░░░░░░   —     失速  ✕    │
│   履带  ░░░░░░░░░░   —     损毁  ✕    │
├──────────────────────────────────────┤
│ ▾ 机动（点击下发指令）                │
│   [ 停止 ] [ 慢速 ] [ 巡航 ]          │
│   [ 全速 ] [ 最大 ]                   │
├──────────────────────────────────────┤
│ ▸ 武器与弹药          主炮 38/40 发   │  ← 折叠态仍显示摘要
├──────────────────────────────────────┤
│ ▸ 传感器 / EMCON      雷达 主动       │
├──────────────────────────────────────┤
│ ▸ 编队 AI             机动 · 通信 87% │
├──────────────────────────────────────┤
│ ▸ 最近事件            3 条            │
└──────────────────────────────────────┘
```

### 3.2 分组定义

| 分组 | 内容来源（`WorldAdapter`） | 折叠态摘要 |
|---|---|---|
| **头部**（固定） | `unit_name` / `side_name` / 工程图 / 选中态 | —— |
| 基本状态 | `armor_yaw` / `speed_at` / `armor_pos` / `armor_formation_id` | 无（默认展开，**双列紧凑**） |
| **状态（MSR）** | `armor_health` → 战备等级；`damaged_parts` / `present_parts` → 子系统能力 | `PMC · 部分可用` |
| 机动 | 命令按钮（见 §3.4） | —— |
| 武器与弹药 | `ammo_at`（后续接 `Magazines` 明细） | `主炮 38/40` |
| 传感器 / EMCON | ⚠️ 引擎暂无 per-unit 传感器开关视图（见 §6） | `雷达 主动` |
| 编队 | `unit_formation_status`（intent/order/comm/member_count） | `进攻 · 通信 87%` |
| 最近事件 | `event_source` 回调（`CombatEventRecorder`） | `3 条` |

> ⚠️ **不要显示「结构 62%」这类百分比**（2026-11-03 定稿）。
> 原因：百分比是 `armor_health` 的物理真值（Real / 上帝视角）；现实里车组只能报
> 「还能不能跑、还能不能打」。这与 Phase 8 战争迷雾的 Real/Twin 原则一致——
> 玩家看到的永远是**认知**，不是**真相**。
>
> 改用 **MSR（装备状态报告）口径**：
> - 战备等级三档：`FMC`（全可用）/ `PMC`（部分可用）/ `NMC`（不可用）
> - 子系统只报能力与影响：`机动 受限 / 左履带断裂`、`火力 可用`、`防护 可用 / 弹药架受损`
> - 弹药数、燃料百分比**可以**显示（车组确实知道剩多少发、油表读数）

**级别 0（无选中）**：头部换成「全局态势」，下挂 `双方兵力 / 平均后勤 / 模拟时间`，其余分组隐藏。
**级别 1（悬浮）**：头部 + 基本状态 + 状态摘要 + 「点击查看完整信息」提示；机动按钮**置灰**（防止误触）。

### 3.3 实现方案

新增 `Airia/ui/collapsible.py`：

```python
class CollapsibleSection(QWidget):
    """可折叠分组（CMO 侧栏风格）。

    - 标题栏 = 三角箭头 + 标题 + 右侧摘要文字（折叠态仍可见）
    - 点击标题栏切换展开/折叠；内容区为任意 QWidget
    - 支持 set_summary(str) 在不展开时更新摘要
    """
    def __init__(self, title: str, expanded: bool = True, parent=None) -> None: ...
    def set_content(self, widget: QWidget) -> None: ...
    def set_summary(self, text: str) -> None: ...
    def set_expanded(self, expanded: bool) -> None: ...
    def is_expanded(self) -> bool: ...
```

`detail_panel.py` 重构为：

```
DetailPanel(QWidget)
 └ QScrollArea
    └ QWidget (VBoxLayout)
       ├ UnitHeader(QWidget)            # 固定头部（缩略图 + 名称 + 徽标）
       ├ CollapsibleSection × N         # 见 §3.2
       └ QSpacerItem
```

**保留**：现有 `_level0 / _level1 / _level2` 的**数据聚合逻辑**（它们已经把 `present_parts` / `part_armor_mm` / `formation_status` 等算清楚了），只把「拼 HTML 字符串」换成「填 widget 字段」。减少回归风险。

**性能约束**：`set_adapter()` 每帧调用（60fps）。分组内容更新必须**只在选中/悬浮对象变化时重建 widget**，同一对象的数值更新走 `QLabel.setText()` 轻量路径。禁止每帧重建控件树。

### 3.4 机动命令（读写成对）

CMO 的 `Stop/Creep/Cruise/Full/Flank` 直接落到命令队列。我们对应：

| 按钮 | `Command` | 说明 |
|---|---|---|
| 停止 | `HOLD` | 已有。清路标点 + 速度 0（`command_router._hold`） |
| 慢速 / 巡航 / 全速 / 最大 | `THROTTLE` + `params={"speed": X}` | ⚠️ **需新增命令类型**，见 §6.1 |

**为什么不用现有 `REDEPLOY` 带 `params.speed`**：`REDEPLOY` 会重设 `target_zone` 并重算全部路标点（`command_router._redeploy`），而「改油门」应该**只改速度、不动航路**。两者语义不可混。

### 3.5 单位图像：军用技术手册 / 蓝图风格

#### 3.5.0 为什么不是「实拍照片」

CMO 的 `UNIT STATUS` 缩略图是**实拍照片**，但那是 1945–2020 年的装备数据库。本项目正篇设定在 **2060 年**（`story/arkady in cradle/《Arkady in Cradle》完整世界观设定（整合版）.md` §3 装备时间线）：

| 年份 | 装备状态 |
|---|---|
| 2030 | 六代机在中美俄常态化服役 |
| 2045 | 第七代战斗机（亚轨道作战平台）设计定型 |
| 2050–2055 | 七代机逐步服役 |
| **2060（正篇）** | 六代机 + 无人僚机普遍；七代机成体系；各国拥有太空军 / 轨道空降编制 |

**主力装备在现实中不存在，因此不存在「实拍照片」。**

结论：不用实拍、**也不用「照片级 CG 顶替实拍」**。2060 年的军方数据库里，装备图本来就该是**技术手册插图 / 工程图纸**——CG 感在此不仅合理，且更贴合世界观。既省掉照片级渲染的巨大美术成本（3–8 人天/件），又形成独特的视觉识别。

> 决策记录（2026-11-03）：用户明确否决「用简陋几何体渲染冒充实拍」，选定**军用技术手册 / 蓝图**风格。
> 注意区分：**蓝图 ≠ 简陋占位**。占位是无信息的色块；蓝图是**精确轮廓 + 尺寸标注 + 剖面 + 数据栏**，每条线都有尺寸依据。

#### 3.5.1 视觉规格

| 元素 | 规格 |
|---|---|
| 尺寸 | 缩略图 256×256（显示时缩到 96×96）；详情页 512×512 |
| 底色 | `#0d1117` |
| 网格 | 16px 细 + 64px 粗，`#1c2733`，40% 不透明度 |
| 主线 | 1.5px，`#9fd8e8`（工程图青白） |
| 外轮廓 | 2.5px，比内部线亮一档 |
| 隐藏线 | 虚线 `#3a4a5a`，35% 不透明度 |
| 阵营标识 | 左下竖条：北约 `#4dd97a` / 华约 `#e63329` / 中立 `#a6a6a6` |
| 数据栏 | 右下 3 行：型号 / 口径 / 乘员 |
| 角标 | 左上 `AIC-DB` + 三位编号，等宽字体 |
| 做旧 | 扫描噪点 + 轻纸张纹理，≤5% 不透明度（**宁少勿多**） |

#### 3.5.2 数据驱动生成管线

```
data/units/<unit_id>.yaml        # 型号定义（部位尺寸、口径、乘员、标注）
        ↓  Pydantic 校验
Airia/render/blueprint.py        # 正交投影 → 线框 → 隐藏线消除
        ↓                         → 尺寸标注 → 数据栏/角标/网格
        ↓                         → PIL 合成
assets/units/thumbs/<unit_id>.webp
```

```yaml
# data/units/m1a2.yaml（示例结构）
m1a2:
  name: M1A2 Abrams
  side: NATO
  role: tank
  parts:
    - {part: hull,   size: [3.7, 7.9, 1.4], pos: [0, 0.0, 0.7]}
    - {part: turret, size: [2.6, 3.4, 1.1], pos: [0, 0.4, 1.9]}
    - {part: gun,    length: 5.3, caliber: 120}
  crew: 4
  annotations:
    - {text: "L 9.8 m", from: hull, to: gun}
```

**红利**：新增单位 = 写一份 YAML，图自动产出。

**数据自洽**：`BoxPool` 的 `box_half` / `box_part` 就是各部位的真实尺寸，图纸尺寸 = 碰撞箱尺寸 = 渲染尺寸，三者同源。

#### 3.5.3 三级精细度

| 级别 | 内容 | 单件成本 | 适用 |
|---|---|---|---|
| **Lv1** | 盒体组合 + 尺寸标注 + 数据栏 | ~20 分钟（写 YAML） | 立刻可用，跑通流程 |
| **Lv2** | 加零件：炮管、负重轮、主动轮、炮塔斜面、天线 | 1–2 小时 | 主力单位 |
| **Lv3** | 导入手绘 SVG 轮廓 / 精细矢量描摹 | ~半天 | 仅主角 |

Lv1 是**真正的图纸**（有尺寸与标注），不是占位；Lv2/Lv3 是增美。

#### 3.5.4 缩略图 vs 详情页

96px 放不下三视图，必须分工：

| 位置 | 内容 |
|---|---|
| 侧栏缩略图 96×96 | **单视角**（3/4 或正侧）外轮廓 + 阵营条 + 编号 |
| 装备详情页（点击缩略图） | **完整三视图**（前/侧/俯）+ 全尺寸标注 + 性能数据栏 |

详情页对应 CMO 的 `Database Viewer`，独立窗口，属后续增强（本设计只预留入口）。

#### 3.5.5 实现约束

- **纯 CPU + PIL，零 OpenGL**：避开 QOpenGLWidget 嵌套 context 的已知雷区（`phase5-ui-pipeline-design.md` §「实施中踩坑」第 3 条）。
- **离线预生成**，不进运行时热路径：图片生成是一次性构建产物，运行时只做 `QPixmap` 加载 + 缓存。
- **回退链**（保证 UI 永不被缺图阻塞）：
  ```
  MANIFEST 有图 → 加载
       ↓ 无
  YAML 存在 → 现场生成一次并缓存
       ↓ 无
  阵营色块 + 型号文字（明确占位，非拟真）
  ```
- **测试产物**走 `tests/output/`（`_output.py`），对照图不入库。

#### 3.5.6 与 3D 低模的关系

本节的蓝图生成器（正交线框）与 §4.4 的场景内 3D 低模（盒体）**共用同一份 YAML 尺寸数据**，但**不共用渲染代码**：一个是 2D 正交线框，一个是 3D 实例化盒体。共用数据、不共用管线，避免耦合。

#### 3.5.7 工程图的内容纪律（2026-11-03 定稿）

原型 `prototype/ui_c4i_demo.py` 验证后确定：工程图**只承载外形与一个主尺寸**。

| 保留 | 移除 |
|---|---|
| 侧视轮廓（车体 / 炮塔 / 炮管 / 负重轮 / 履带） | ~~`120MM` / `CREW 4` / `M1A2 ABRAMS` 数据栏~~ |
| 一条总长尺寸线（`L 9.8 m`，文字压线断开） | ~~多条尺寸标注~~ |
| 左上阵营色块（7×7） | ~~角标编号 `MBT-003`~~ |

理由：口径与乘员数属**装备数据库**信息，不是**战术决策**所需；放在侧栏只会挤占空间。若将来需要，进「装备详情窗」（Database Viewer），不进缩略图。

### 3.6 视觉规范定稿（原型验证版）

#### 3.6.1 风格定位

放弃初版的「深空 + 霓虹青」科幻风，改为**现实军事 C4I** 语言。
依据：GCCS-J / C2PC / JBC-P / MCS / AFATDS / CPOF 的共性——低饱和、小字号、高密度、
方角、无圆角无渐变、语义色严格固定。

**两套主题并存**：

| 主题 | 定位 | 场景 |
|---|---|---|
| `light` | 指挥所工作站 | 白天推演、会议室投影、长时阅读 |
| `dark` | 车载 / 野战战术终端 | 夜战、装甲指挥车、剧情演出 |

#### 3.6.2 布局形态：地图铺满 + 浮层

## 四、B 线：战场符号层

### 4.1 三层结构

```
        符号层（永远屏幕对齐，语义层）
              ↑ 朝向楔 + 编号 + 选中环
        标签层（三行挂载，随 LOD 显隐）
              ↑ 名称 / 航向 / 速度
        模型层（3D 低模，随距离淡入淡出）
              ↑ 程序化盒体
```

**关键原则**：符号**永不消失**，模型可淡出。这保证任何相机角度下战场都可读——这是 CMO 的味道，也是 3D 相较于纯 2D 必须补上的一课。

### 4.2 朝向楔（替换圆点）

现有 `HUDOverlay` 只有 `mode 0`（实心圆）和 `mode 1`（圆环）。新增 `mode 2`：**朝向楔**。

顶点着色器需要每实例的 `yaw`：实例 buffer format 从 `"2f 1f 3f /i"` 扩为 `"2f 1f 3f 1f /i"`（`in_center, in_radius, in_color, in_yaw`），在 VS 内旋转 `in_quad`：

```glsl
vec2 dir = vec2(sin(in_yaw), -cos(in_yaw));   // 屏幕 y 向下
// 楔形 = 单位圆上 [-0.45π, +0.45π] 的扇区，顶点沿 dir 拉长
```

屏幕上形成一个「箭头」，yaw 一转就转。数据已就绪：`adapter.armor_yaw[i]`。

> 注意：`armor_yaw` 是世界坐标系朝向，`project_world` 只给屏幕位置。楔的屏幕角度需要**相机 yaw 参与**才能正确显示（否则相机一转，箭头全指同一方向）。实现时取 `screen_yaw = world_yaw - camera_yaw`（俯视近似），相机 pitch 大时误差可接受；若追求精确，改用两个世界点投影求屏幕方向（`pos` 与 `pos + dir*50m`），成本极低且完全正确。**推荐后者**。

### 4.3 三档 LOD

| 档 | 触发条件 | 模型层 | 符号层 | 标签层 |
|---|---|---|---|---|
| **近** | 相机 `distance < 800m` | 完整低模 | 朝向楔 + 选中环 | 全名 + 编号 + ⚠损坏 |
| **中** | `800 ≤ distance < 3000m` | 简化低模 | 朝向楔 | 型号 + 编号 |
| **远** | `distance ≥ 3000m` | 无 | 仅朝向楔（4px） | 无 |

**密度保护**（与距离无关的额外规则）：可见单位 > `80` 时，屏幕半径 < 12px 的簇只画符号不画标签，避免 `_render_labels` 满屏文字。当前该函数对**所有可见单位**无条件画名字（`gl_widget.py:519`），是必须补的洞。

LOD 阈值放在 `render/units.py` 的常量里，便于调参与单测。

### 4.4 场景内 3D 低模（盒体，零美术资源）

`BoxPool` 已有每个单位 2~6 个碰撞箱，含 `box_half`（局部半边长）与 `box_part`（部位类型）。**这就是低模**：直接按部位画盒体，颜色按部位区分（车体/炮塔/引擎/履带/弹药架），炮塔沿 yaw 转、其余锁车体。

> 与 §3.5 的**蓝图生成器**共用同一份 YAML 尺寸数据，但**不共用渲染代码**：
> §3.5 是 2D 正交线框（PIL，离线预生成）；本节是 3D 实例化盒体（moderngl，每帧）。
> 共用数据、不共用管线。

| 收益 | 说明 |
|---|---|
| 零资源 | 不需要 `.obj` / 美术管线 |
| 数据自洽 | 模型尺寸 = 碰撞箱尺寸，所见即所中（未来做 3D 拾取时不会错位） |
| 部位可见 | 引擎/履带被毁时可单独变色或标记，损伤可视化直接落在模型上 |

渲染方式：实例化渲染，`u_instance_kind` 区分前几个部件；或先只做「车体盒 + 炮塔盒 + 炮管」三件套，管用即可。

### 4.5 俯视冲突处理

CMO 只有 2D，不存在「模型剪影与军标打架」。我们有。

**已定方案（2026-11-03）：自动规则 + 手动开关，手动优先。**

```
手动开关（硬覆盖，优先级最高）
  ├─ 「仅符号」   → 任何 pitch 都不画模型
  ├─ 「显示模型」 → 任何 pitch 都画模型（俯视时也画）
  └─ 「自动」（默认）→ 走下面的自动规则
        pitch > 80°  模型完全隐藏，退化为纯符号地图
        pitch > 65°  模型整体不透明度降至 0.35（符号层保持 100%）
        否则          正常显示
```

这样「拉平看模型、拉高看态势」默认不用玩家操心，同时给偏好纯符号地图的玩家一个硬开关。

开关位置：动作栏 `面板▾` 或视图菜单，三态（自动 / 仅符号 / 显示模型）。

### 4.6 比例尺

右下角固定像素长度（取 120px），反算世界米数 → 取整到 `1/2/5 × 10ⁿ` → 重算像素长 → 画线 + 文字（复用 `TextRenderer`）。

取整函数纯逻辑，可单测：
`nice_scale(world_per_px, target_px=120) -> (nice_meters, actual_px)`

### 4.7 光标坐标

鼠标位置 → 屏幕 → 反投影到 `z = 0` 平面（相机位姿已知，`picking.py` 已有投影逻辑，反投影是它的逆运算）→ 底部中央显示：

```
X 1243 m  Y 881 m   地形 4 m
```

（若 `coordinates/` 模块的 ENU 已可用，可切换显示 UTM/经纬度，本设计默认米制。）

### 4.8 射程圈

选中单位时画其武器最大射程圈。**数据已就绪**：`WeaponConfig.max_range_m`（`combat/weapons.py:195`）、`EngagementConfig.max_range_m`。

实现：圆周采样 64 点 → `project_world` → `HUDOverlay.render_lines` 折线。透视下自然成椭圆，无需特殊处理。

⚠️ 需装配层提供「单位 → 武器射程」查询。当前 `WorldAdapter` 没有这个视图，见 §6.2。

## 五、C 线：外围控件

### 5.1 时间压缩条

| 档位 | `time_scale` |
|---|---|
| ⏸ | 0（复用 `_manual_paused`） |
| 1x / 2x / 5x / 10x | 1 / 2 / 5 / 10 |

实现：`MainWindow._on_frame` 中 `self.simulation.step((1/60) * self._time_scale)`。

**风险**：`SimulationLoop.step(dt)` 把 `dt` 直接累加进 `sim_time` 并喂给子系统速率累加器（`loop.py:210-217`）。放大 10 倍 = 单帧 0.167s，可能导致：
- 子弹高速穿透（碰撞已用胶囊体线段检测，理论上免疫，但需压测验证）
- 地面 Tick 一次跳多拍，AI OODA 循环节奏变化

**处置**：**先做 1x/2x/5x，10x 标为"实验档"**，并补一个压测用例（`tests/benchmark_time_scale.py`），比对 1x 与 5x 跑 60s 后的单位存活数/弹药消耗是否同量级。若不可接受，退回"内部固定 dt 多次 step"的方案（即 5x = 每帧 step 5 次 1/60）。

> 后者更安全，且实现同样简单：`for _ in range(n): simulation.step(1/60)`。**建议直接采用这个方案**——它是物理正确的，而"放大 dt"只是近似。

## 九、与既有约定的关系

- **不改依赖方向**：所有新增 UI 文件在 `Airia/ui/` 与 `Airia/render/`；引擎改动仅在 `Airia/lulilo/simulation/`。`render` 仍只读 `WorldAdapter`。
- **不破坏 Phase 5 验收**：主题热切换、拾取、对话选项、快捷键全部保留；`DetailPanel` 的 `set_hover/set_selection/set_adapter` 三个公开方法签名不变（内部实现换掉）。
- **战争迷雾兼容**：所有新 UI 元素读的仍是 `WorldAdapter` 字段（`confidence` / `status`）。`from_snapshot_twin` 切换后，折叠分组与符号层**零改动**即获得迷雾表现——只需在符号层按 `status` 换符号形状（UNKNOWN=「?」、KIA=残骸+叉、MIA=灰框闪烁）。
- **测试产物**：缩略图/比例尺的对照图一律走 `tests/output/` 与 `_output.py`。
