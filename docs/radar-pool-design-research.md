# 雷达池 / 辐射源池设计可行性研究

> 状态：**研究稿（2026-11-05），未写任何代码**
> 缘起：`docs/对雷达等设计的讨论.md`（用户喵的提案）
> 结论先行：方案总体可行且方向正确，但需要把「雷达（接收）」与「辐射源（发射）」
> 拆成两个池、把「扫描锥」升级为「波束足迹 + 扫描相位 + 驻留预算」、
> 把「coherence」拆成「相干性 + 反射模型」，并且**检测结果必须写成测量量而不是真值**。
> 这样「必须模拟目标鉴别才能显示敌人」这句担心，反而变成战争迷雾的现成收益。

## 一、提案复述与判定

用户提案的四条：

| # | 提案 | 判定 |
|---|---|---|
| 1 | 像装甲池/碰撞箱池一样，雷达提交扫描范围（三角锥、可旋转、可锁定/反复切换、可改频道） | ✅ 可行；锥 → 足迹 + 扫描相位 + 驻留预算 |
| 2 | 雷达可改自己 ID 条目的数据 | ✅ 与 SoA 池范式完全一致（AI 在 Python 冷路径改写数组即可，不影响 Numba 缓存） |
| 3 | Emitter 也是类似的池，frequency 决定波段、coherence 决定直射/漫射，交给 NumPy/Numba 并行算 | ⚠️ 半对：波段字段要补，但 coherence ≠ 直射/漫射（见 §三.2） |
| 4 | 探测结果直接回写到雷达预留空间（RCS/特征/方位/多普勒），省函数调用，方便导引头 AI | ✅ 强烈同意；但**并行内核里不能用自增计数器**（见 §五.2） |
| 5 | 缺点：必须真正模拟目标鉴别才能可视化敌方位置 | 🔁 这不是缺点，是目标；项目已有 Twin/COP 骨架，正好承接（见 §七） |

## 二、现状盘点（代码事实）

现状不是「没有雷达」，而是**每个消费者自己拼一条检测链路**，没有统一的设备实体：

| 位置 | 现状 | 缺口 |
|---|---|---|
| `entities/pools.py:1075` `EmitterPool` | 4096 容量；`band(0RF/1IR/2LASER)`、`kind`、`cur_power`、`parent_kind/parent_idx`、`normal`（仅激光光斑） | **无频率、无带宽、无增益、无波束、无相干性、无反射模型**；只有一个 `power_db` 标量过公式 |
| `entities/pools.py:192` `ArmorPool.rcs/ecm` | 每车一个 `float32` 标量 | 无视角依赖 RCS、无起伏模型；ECM 只是一个 0~1 折扣系数 |
| `detection/sensors.py:212` `evaluate_sensor_detection` | N×M 距离门限；`sensor_type` 0/1/2 选公式 | 每雷达功率/频率/增益**全部走默认值**；无 FOV、无扫描、无多普勒 |
| `detection/sensors.py:45` `radar_detection_range` | `R ∝ σ^0.25`，功率/增益线性修正 | 算了 `wavelength` 却**从未使用**；没有 B/F/SNR_min/驻留时间 |
| `simulation/air_ai.py:100` `gather_air_contacts` | 机载雷达搜索 + 地平线 + LOS + 概率采样 | 形参 `radar_power_db` **是死参数**（只出现在 docstring） |
| `simulation/ai.py:377` `RWRDetector` | 逐单位 Python 遍历 emitter，`esm_detection_range(power)` | 不看频率、不看方向、不看接收机波段 |
| `movement/integrate.py:770` | 导引头 FOV（`guid_search_fov_cos/track_fov_cos`）在弹道积分里 | 第三套独立的「视场」实现 |
| `simulation/twin_engine.py` | 观测注入 + 数据链融合 + 时间衰减 + 延迟报告 | 只在测试里被实例化；**主场景 `world1.py` 没有 TwinEngine，也没 attach "detection"**；`FormationAI` 默认全知读真值 |

一句话：**地面部队目前是上帝视角，雷达/传感器链路没有接线**。雷达池不是锦上添花，
它正好补上 Phase 8 落地时留下的这个洞。

## 三、两个关键概念澄清

### 3.1 Radar 与 Emitter 是同一设备的两面，但应该分池

- `EmitterPool` = **我向外发射什么**。消费者是**敌方**的 ESM/RWR/ARM/反辐射导引头。
  红外源、诱饵、激光光斑都只有发射面，没有接收面。
- `RadarPool` = **我能看到什么**。消费者是**己方**的检测融合 / 孪生 / AI。
  被动 IRST、ESM 接收机、激光告警都只有接收面，没有发射面。

分池的理由不是洁癖，是四条硬差异：

1. **消费者阵营不同**（发射面被敌人消费，接收面只被自己消费）→ 数据可见性边界天然不同；
2. **生命周期不同**（诱饵/光斑/殉爆脉冲无雷达；被动接收机无发射）；
3. **tick 档位不同**（发射面随父实体每帧同步；接收面按地面 1s / 空中 0.5s / 火控 0.1s 分档）；
4. **扩容与序列化粒度不同**。

用 `radar.emitter_idx`（-1 = 纯被动）单向链接即可，不需要双向冗余字段。
`sensors.py` 的既有信号是内核只吃裸数组、不 import 池——新内核保持同样风格。

### 3.2 coherence 不等于直射/漫射

物理上「相干」说的是相位关系可预测，能带来脉压、MTI、相位测角、SAR 等能力；
「直射 vs 漫射」是**反射/散射几何模型**；而红外根本不存在 coherence 这个量。

建议拆成三个正交字段：

```
band            : 0=RF 1=IR 2=LASER        # 决定用哪条链路预算
phase_coherent  : bool                     # RF/LASER 才有意义；IR 恒 False
reflection_model: 0=SPECULAR 1=DIFFUSE 2=GLINT
```

- 雷达回波：`SPECULAR`（镜面强闪）+ 统计起伏（Swerling）比逐面法线便宜得多；
- 激光光斑：`DIFFUSE` + 已存的 `normal` 半球判定（沿用现状）；
- 红外：`DIFFUSE` + 无相干；
- 噪声干扰机 / 箔条：`INCOHERENT`，只能抬噪底，不能形成假航迹；
- DRFM 欺骗干扰：`COHERENT`，**能**形成假航迹——这才是「鉴别」真正的对手。

## 四、物理模型：只做 L1，明确拒绝 L2

| 档 | 内容 | 用途 |
|---|---|---|
| L0 | 现状：`R_max = f(RCS, P)` + S 曲线概率 | 大量次要单位 |
| **L1（推荐）** | 单站雷达方程 + 天线方向图 + 波束足迹/扫描相位 + 驻留积分 + 多普勒 + 测量噪声 | 主战雷达、机载雷达、火控 |
| L2 | 脉压/HRRP/ISAR/极化/多径 | **不做**，交给叙事文本 |

### 4.1 链路预算（dB 形式，便于 YAML 配置）

```
SNR = Pt + Gt + Gr + 20log10(λ) + 10log10(σ) − 30log10(4π)
      − 10log10(k·T0·B·F) − L − 40log10(R)
```

关键点：`R` 每翻 4 倍，SNR 掉 12dB。想让某雷达对 30m² 坦克看 25km，反推
`Pt/NF/B/SNR_min` 即可，不必拍脑袋定 `ref_range`。

**驻留积分增益**（这是「锁定/反复切换」的物理抓手）：

```
SNR_total = SNR_pulse + 10log10(T_dwell / T_pulse)
```

搜索驻留 10ms、跟踪驻留 100ms → +10dB → `R_max × 1.78`。于是「相控阵把资源分给
几个目标」变成一句可算的话：**一部雷达的驻留时间是预算，锁定目标 = 抢驻留**。

### 4.2 天线方向图（让「锥」有物理意义）

高斯近似，双程：

```
g(θ) = G_max − 12·(θ / θ_3dB)²   [dB]
```

`θ` = 视线与波束轴的夹角。波束边缘 SNR 骤降 → 检测距离骤降，这才是「扫描锥」而不是
「一个球形 R_max 再乘个布尔 FOV」。

### 4.3 多普勒与 MTI（最便宜的「目标鉴别」）

```
f_d = 2·v_r / λ,   v_r = −(v_t − v_radar)·LOS
|v_r| < v_notch  →  P_d ×= exp(−(v_notch/|v_r|)²) 左右（近似）
```

效果：慢速/横穿目标在 MTI 雷达上时隐时现；这既是真实感，也是分类特征
（坦克 vs 直升机 vs 固定翼的多普勒差是数量级）。

### 4.4 测量噪声（决定「雷达屏幕感」）

```
σ_R      = R_max / (SNR_linear)^0.5      # 距离
σ_az     = θ_3dB / (SNR_linear)^0.5      # 方位
σ_v      ~ λ / (2·T_dwell) / SNR^0.5     # 速度
```

**检测结果写 `(R, az, el, v_r) ± σ`，永远不写目标真值笛卡尔坐标。**
这一条是「渲染层不能作弊」的物理保证，比任何代码规范都硬。

## 五、数据布局与内核

### 5.1 `RadarPool`（新池，建议容量 2048，与装甲同量级）

设备行（每雷达一份，全部 `np.float32/int32/bool_`）：

```
# 绑定与生命周期
parent_kind, parent_idx, active          # 沿用 EmitterPool 三态（含战术关机保留索引）
emitter_idx                              # 发射面链接，-1 = 纯被动

# 波束 / 足迹
boresight(3), az_center, az_width, el_center, el_width
fov_shape(0=CONE 1=RECT), cos_half_angle, range_min, range_max

# 扫描调度
scan_mode(0=STARING 1=CIRCULAR 2=SECTOR 3=TWS)
scan_period_s, scan_rate_dps, scan_phase_deg(0..360), t_last_dwell
dwell_search_s, dwell_track_s, track_capacity, revisit_s

# 接收机
band, freq_ghz, bandwidth_mhz, gain_db, noise_figure_db, loss_db, snr_min_db
mti_notch_mps, pd_scale

# 光学/红外参数（band=IR/LASER 用）
aperture_m2, nefd, laser_gate_ns   # 可选，先留字段

# 锁定（由 AI 在 Python 冷路径写）
locked_kind, locked_idx, lock_quality, next_dwell_at(3)

# ---- 结果区（预留空间，内核直接写）----
det_count            (N,) int32
det_tgt_kind         (N, K) int32      # 0=装甲 1=飞机 2=弹丸 3=辐射源
det_tgt_idx          (N, K) int32
det_range            (N, K) float32
det_az, det_el       (N, K) float32
det_range_rate       (N, K) float32    # 多普勒
det_rcs              (N, K) float32
det_snr_db           (N, K) float32
det_quality          (N, K) float32    # 0~1，喂 twin confidence
det_meas_sigma       (N, K, 3) float32 # σ_R, σ_az, σ_v
```

`K`：搜索雷达 16，火控 4。2048×16×~14 字段×4B ≈ **1.8MB/方**，可接受。

### 5.2 并行内核：行独占 + 两遍法（**不要原子自增**）

Numba CPU 没有 `atomic_add`（只有 CUDA 有）。项目红线也写了「禁止在 prange 做非原子写入」。
正确写法：**prange 的每一趟只写自己那一行，计数器是线程局部变量**。

```python
@njit(cache=True, parallel=True)
def radar_scan_kernel(...):
    for r in prange(n_radar):                    # 每雷达独占一行
        if not r_active[r]:
            continue
        k = 0                                     # 线程局部，无竞争
        for t in range(n_tgt):
            if not tgt_active[t]:
                continue
            # ① 最便宜的门先在前面：距离² 门限（无 sqrt）+ 波束点积
            if d2[r, t] > rmax2[r]:
                continue
            if dot(boresight[r], los_unit[r, t]) < cos_half[r]:
                continue
            # ② 只有候选才做：方向图、SNR、多普勒、PD 采样
            snr = link_budget(r, t)
            if snr < snr_min[r]:
                continue
            if rng.uniform() > pd(snr, ...):
                continue
            det_count[r] = k + 1
            det_*[r, k] = ...
            k += 1
            if k >= K_MAX:
                break
```

要点：

- **LOS 遮挡绝不能在 pair 循环里做**。先出候选（FOV 门限后通常 < 2%），
  再对候选做 DDA（`detection/los.py`）——这一步放在 Python/向量化后处理，或按 site 缓存。
- **缓冲全部预分配**，不在 tick 里 `np.zeros((N,M))`。现状 `air_ai.gather_air_contacts`
  每个 tick 分配一次 `max_range_cache`，属于可顺手消灭的 GC 压力。
- 需要「所有目标对」的中间量时，用持久化的 `(N_active, M) float32` scratch，
  按 `active` 数切片使用，不重建。

### 5.3 `EmitterPool` 增补（只加字段，不动语义）

```
freq_ghz, bandwidth_mhz, gain_db, beam_cos, polarization
phase_coherent, reflection_model
jam_technique(0=噪声 1=DRFM 2=无), erp_db
```

全部给默认值 → 现有导引头/ARM/RWR/诱饵/光斑链路行为不变，只是开始能读频率。
`heading/attitude` 用于波束指向：可由 `parent_kind` 从父实体即时取，不用新数组。

## 六、扫描 / 驻留 / 跟踪调度模型

| 雷达类型 | 参数 | 行为 |
|---|---|---|
| 旋转预警 | `scan_mode=CIRCULAR`, `scan_rate_dps=60`（10rpm）, `az_width=2` | 每 6s 覆盖 360°；目标每 6s 有一次 33ms 驻留机会 |
| 扇扫 | `SECTOR`, 中心 ±30° | 只看指定扇区，相位往返 |
| 相控阵搜索 | `TWS`, `revisit_s=2`, `track_capacity=10` | 电扫无惯性，但驻留预算有限 |
| 相控阵火控 | 锁定后 `dwell_track_s=0.1`, `revisit_s=0.2` | +10dB、更新率 5Hz、可同时 1~2 个目标 |
| 被动 ESM/IRST | `emitter_idx=-1` | 只做接收，不参与发射暴露 |

**相位必须用绝对时间算，不要累加**（否则 tick 抖动会造成漂移）：

```
phase = (phase0 + 360 * (t_abs / scan_period_s)) mod 360
```

「目标是否在本次 tick 被扫到」= 相位窗口与目标方位角的交集。
代价：AI 反应时间被扫描周期量化（很有戏），但也让自动化测试变脆 → 测试里给
`scan_period_s=1e-6`（等效瞬时全向）的调试雷达。

## 七、目标鉴别与战争迷雾：把「缺点」变成特性

### 7.1 检测结果不写真相

`RadarPool` 的输出是**测量量**（距离/方位/俯仰/多普勒 + 噪声），不是 `armor.pos`。
渲染与 AI 都读不到真值，这从数据流上封死了上帝视角。

### 7.2 四级识别（每级决定 UI 画什么）

| 级 | 获得信息 | UI |
|---|---|---|
| DETECTED | range + az + 时间戳 | 一个 blip（扇形/光点），无位置解算 |
| TRACKED | 位置 + 速度（多普勒/多次观测） | 带速度矢量的接触框 |
| CLASSIFIED | 类别：坦克/步战/飞机（RCS 幅度+起伏+多普勒+IR 比） | 图标从 `?` 变成车型轮廓 |
| IDENTIFIED | 阵营/型号（ESM 频点、IFF、编队情报） | 完整单位卡 + 型号名 |

现有 `TwinPool` 已经有 `status / confidence / pos_err / source`，只差一个
`id_level`（int8）+ `class_kind`。渲染层按 `id_level` 切换绘制，与主题商店解耦。

### 7.3 分类器不需要 ML

用一个配置表做最近质心即可，特征只有 4 个：

```
mean_rcs, rcs_fluctuation(起伏指数), |v_r|, ir/rcs 比
```

- 坦克：rcs 大、起伏低、v_r 低；
- 直升机：rcs 小、v_r 中等、IR 高；
- 固定翼：rcs 中、v_r 高、IR 中；
- 诱饵/角反射器：rcs 大但起伏异常、无 IR → **误判为坦克**（这就是欺骗的意义）。

### 7.4 与孪生的接线（现成的）

```
radar_scan_kernel → det_* 行
   → TwinEngine.observe(kind, idx, pos=测量解算位置, confidence=det_quality,
                        observer_comm=观测者通信值)
   → twin 多源融合 / 衰减 / 数据链共享
   → FormationAI（TwinContactProvider）+ 渲染（adapter.from_snapshot_twin）
```

`TwinEngine` 的四条通道、`pos_err = 50*(1-conf)`、KIA/MIA 双通道全都可复用，
**不需要为雷达单独造一套「接触表」**。现在的 `AirContact` 列表可以退化成
「雷达 det 行的 Python 视图」，等 P3 再合并。

## 八、迁移路径（P0→P5，每步可独立验收）

| 步 | 内容 | 验收 |
|---|---|---|
| **P0** | `EmitterPool` 补 `freq/bandwidth/gain/coherence/reflection/jam`（全默认值）；`ArmorPool.rcs` 保留标量，另加可选 `rcs_front/side/top` 三值 | 383+ 测试全绿；存档往返；无行为变化 |
| **P1** | `RadarPool` 骨架 + `radar_scan_kernel`（FOV 门限 + 距离门限 + det 行回写）+ 序列化 | 锥内/锥外、距离门限、`det_count` 正确、无越界；两方雷达互不干扰 |
| **P2** | 方向图 + 驻留积分 + PD 采样 + 多普勒/MTI + 测量噪声；扫描相位 | 旋转雷达 6s 覆盖 360°；锁定 +10dB；SNR 每 4× 距离 −12dB；慢目标 MTI 丢失 |
| **P3** | 接 `TwinEngine` + `FormationAI(contact_provider=...)` + 渲染 `id_level`；`world1` 接 `detection` hook | 开机出 blip、关机后 `UNKNOWN`、AI 不再全知；场景冒烟可跑 |
| **P4** | 干扰源 emitter（噪声/DRFM）+ J/S 闭环 + RWR 频率分档 + 诱饵假 blip | 噪声干扰降低检测距离；诱饵产生假接触；ARM 仍能反辐射 |
| **P5** | 性能：分档 tick（地面 1s / 空中 0.5s / 火控 0.1s）+ 均匀网格粗筛 + benchmark | 2048 雷达 × 2048 目标 < 8ms（1s 档）；内存 < 25MB |

**前置条件**：P3 必须先让 `world1` 接上 `detection` 与 `TwinEngine`——否则雷达池
算出来的东西没有人消费。

## 十、陷阱清单（本项目专属）

1. **prange 里自增计数器** → 非原子，结果丢行。用行独占 + 线程局部 `k`（§五.2）。
2. **LOS 放进 pair 循环** → 2000×2000 次 DDA，直接卡死。必须先候选后遮挡。
3. **tick 里分配数组** → GC 抖动（现状 `air_ai` 已有此问题）。全预分配。
4. **Numba 缓存**：改 `RadarPool` 字段/内核签名后必须 `uv run python clear_numba_cache.py -y`。
5. **扫描相位累加** → 用绝对时间算，别 `phase += rate*dt`。
6. **检测/孪生/AI 三份接触副本** → 以 twin 为唯一 COP，det 只做原始观测；否则三处状态互相打架。
7. **把真值写进 det** → 渲染/AI 会作弊，战争迷雾失效。
8. **频率字段只写不读** → 现状已有先例（`radar_power_db` 死参数）。P1 起就让
   频率进公式并被 RWR/干扰消费，否则又是死字段。
9. **ECM 继续用 `armor.ecm` 标量** → 无法表达「干扰机在哪、什么频段、多大功率」。
   真正的 J/S 必须由 emitter 参与（P4）。
10. **存档漏字段** → `serialization.py` 的 emitters 段模式照抄，注意 `_pack_pool_arrays` 字段列表。
11. **测试确定性**：PD 采样用 `RNGManager` 的独立流（按雷达索引），否则并行顺序一变结果就变。
12. **雷达池容量与真值可见性**：`RadarPool` 只被己方消费，别让渲染层按 `det_*` 反查真值索引——
    `det_tgt_idx` 是给模拟/孪生用的，渲染只应拿「已解算的接触坐标」。

## 十一、需要拍板的开放问题

1. **RCS 视角表要不要做？** 每单位 3~6 个数（前/侧/顶）能让「侧面对雷达更亮」成立，
   成本极低；不做则所有方向一样亮。
2. **雷达池容量 2048 还是 512？** 2048 = 每车一部（含光学/红外传感器位）；
   512 = 只有雷达车/防空车/飞机。
3. **「扫描到才出现」要不要保留？** 真实感强，但 AI 反应时间被量化，
   自动化测试需要用调试雷达（`scan_period≈0`）。
4. **导引头要不要并入雷达池？** 建议先不并：导引头 0.01s 档、只打一个目标，
   现有 `guid_*_fov_cos` 路径已经够快；只把它的频率/功率写进 emitter 保证 RWR/ARM 一致。
5. **地面 detection hook 何时接线？** 这是 P3 的前置项，建议单独排一步，
   顺便把 `FormationAI` 的默认全知源换掉。

## 十二、一句话总结

> 雷达池和辐射源池该建，但要**分池**（发射面给敌人看、接收面给自己看）；
> 锥要变成**足迹 + 扫描相位 + 驻留预算**；coherence 要拆成**相干性 + 反射模型**；
> 结果回写要用**行独占的两遍法**而不是原子自增；检测结果必须是**测量值**——
> 因为「必须模拟目标鉴别才能显示敌人」不是代价，那就是战争迷雾本身。

## 十三、附录：雷达回波到底怎么算（2026-11-05 追问补充）

### 13.1 先定性：我们不要波形，要观测量

真实雷达回波是一段复基带采样，做脉压/MTI/CFAR 之后得到距离-多普勒图。
本项目 tick 是 1s，**不可能也不必要**逐脉冲积分（10ms 驻留 = 100 个脉冲/驻留）。

所以在引擎里，「回波」等价于**一次带噪声的测量采样**，每个 (雷达, 目标, 驻留) 只产出
十来个 float：

```
det_range, det_az, det_el, det_range_rate, det_rcs_est,
det_snr_db, det_quality, det_extent, det_glint, det_range_bins
```

把这十个数量化成「回波」，其余（相位、脉冲、滤波）全部用解析公式折叠掉。
这既满足「AI/渲染直接读」，又不用建信号处理栈。

### 13.2 四档模型（按 LOD 选，不是按目标类型选）

| 档 | 内容 | 何时用 | 成本 |
|---|---|---|---|
| **E0 点目标** | 标量 RCS → 链路预算 → SNR → PD 采样 | 全 pair 粗搜索（每 tick 所有目标） | 每 pair ~10ns |
| **E1 相参点目标** | 加相位 / 多普勒 / 相位噪声 | 需要 MTI、测速、SAR 时 | +sin/cos |
| **E2 扩展目标** | 多散射体复数和（复用 BoxPool） | **只对已检测/已跟踪目标**（~500 个） | 每目标 ~6 个散射体 |
| **E3 环境** | 主瓣杂波 + 大气 + 地平线 + 部件遮挡 | 同上，可与 E2 同趟算 | 每 pair 一条公式 |

关键：**E2/E3 绝不进全 pair 循环**。粗搜索永远只有 E0 + FOV 门限。

### 13.3 E0：点目标回波

```
SNR = Pt + 2G + 20log10(λ) + 10log10(σ) − 30log10(4π)
      − 10log10(k·T0·B·F) − L − 40log10(R) + 10log10(T_dwell/T_pulse)
```

最后一项是驻留积分增益（已写在 §4.1）。检测判定用 Swerling 模型而不是硬阈值：

- **Swerling I（慢起伏，扫描间）**：每个驻留重新抽一个 RCS 起伏因子 ——
  最便宜的实现是 `σ_eff = σ · Exp(1)`（`np.random.exponential` 一行，均值不变），
  然后 `Pd = Pfa^(1/(1+SNR))`。
- **无起伏（校准目标/角反射器）**：直接 `Pd = 1 − ...` 固定。

> 为什么值得抽这一下：坦克 RCS 的闪烁有 10~20dB 起伏，PD 因此剧烈变化。
> 不抽的话，探测就是「进圈必现」的死板开关；抽了之后才有「时隐时现」的雷达感，
> 而且**免费得到「目标鉴别」的第一个特征**（起伏指数）。

### 13.4 E1：相位只取相对值（float32 陷阱）

想算相干叠加就需要相位 `φ = 4πR/λ`。但：

- R = 10km、λ = 0.03m → `4πR/λ ≈ 4.2e6 rad`；float32 相对精度 1e-7 →
  **绝对相位误差 ~0.4 rad**，直接把相干性算错。
- 更本质的是：目标 1s 移动 10m = 667λ，跨驻留相位**完全去相干**。
  所以「跨 tick 记住相位」在物理上就是错的。

正确做法：

1. **只用相对相位**：以目标中心为参考，`ΔR = R_s − R_0`（≤ 10m），
   `φ_s = 4π·ΔR/λ`（≤ 4200 rad，float32 误差 4e-4 rad，够用）。
   公共相位对幅度无贡献，直接扔掉。
2. **每个驻留独立抽公共相位**（均匀 0~2π），不跨 tick 复用。
3. 真要算绝对相位，那一处用 float64。

这和「回波是观测量不是波形」一致：相位只在**同一驻留的散射体之间**才有意义。

### 13.5 E2：扩展目标 —— 直接拿 BoxPool 当散射体

这是本项目最省事的一步：**碰撞箱池天生就是散射体集合**。

`BoxPool` 现有字段完全够用（`pools.py:596`）：

| 字段 | 含义 | 在回波里的角色 |
|---|---|---|
| `parent / parent_kind` | 所属装甲/飞机 | 散射体归属 |
| `local` | 车体局部偏移 | 散射体相对位置（权威） |
| `pos` | 世界坐标（每 tick sync） | 散射体世界位置 |
| `half` | 局部半边长 | 投影面积 / 遮挡体 |
| `part` | HULL/TURRET/ENGINE/TRACK/AMMO_RACK | 面 RCS 表索引 |
| `active / hp` | 部位存活 | **毁伤改变雷达特征** |

每部位给「三面 RCS」（前/侧/顶），不必写 `4πA²/λ²`（平板公式会算出百万 m²，
纯属浪费）——车辆是曲面+吸波，用实测经验值：

```
part           front   side   top     (m², X 波段)
HULL            8.0    16.0    6.0
TURRET         10.0    6.0     4.0
ENGINE          2.0    3.0     1.5
TRACK           1.0    4.0     0.5
AMMO_RACK       0.5    0.5     0.3
```

取法：把战场视线方向变换到车体局部系（`yaw` 逆旋转，碰撞检测里已有这套代码），
看哪个轴占主导 → 取对应面 → 乘以 `|cos|` 投影因子。**无三角函数、无开方**。

求和两种做法：

```python
# ① E2-lite：非相干功率和（默认，便宜且稳定）
sigma = Σ_faces  face_rcs * |cos_aspect|

# ② E2-full：相干复数和（要起伏/角闪烁/多普勒展宽时才开）
a_s   = sqrt(sigma_s) / R_s**2                     # 幅度
phi_s = (4*pi/lam) * (R_s - R_0)                   # 相对相位（§13.4）
echo  = Σ_s a_s * exp(1j*(phi_s + 2*pi*f_d_s*t))   # 一次驻留内
sigma_eff = |echo|**2 * 4*pi*R**4/...              # 反推等效 RCS
```

相干和的三个白送产物：

| 产物 | 表达式 | 量级（T-72，X 波段） |
|---|---|---|
| **RCS 起伏** | `\|echo\|²` 随 `φ_s` 变化 | 10~20dB（Swerling 自然涌现） |
| **距离展宽** | `max(R_s) − min(R_s)` | 侧面 ~7m；0.5m 分辨率下 14 个距离单元 |
| **角闪烁** | 双散射体张角 `L⊥/(2R)` | 10km 处 0.15 mrad；1km 处 1.5 mrad |
| **多普勒展宽** | `2ω·L⊥/λ`（车体转动） | 20°/s、3.5m → ~80Hz |

诚实评价：

- **角闪烁对坦克不重要**（0.15 mrad ≪ 2° 波束），只有对飞机/舰船和近距离才显眼。
  别为它单独建模块，相干和里顺手出即可。
- **真正的收益是距离展宽 + 起伏**：展宽是「分类」的核心特征（3m 分辨率下一辆坦克
  占 2~3 个距离单元，卡车 4~5 个，人 1 个）；起伏是「真假目标」的核心特征。
- **部件毁伤 → RCS 变化**：炮塔被打掉后 `TURRET` 失活，RCS 掉 30%，
  于是「残骸」和「活车」在雷达上可区分。这是叙事层可以直接消费的信号。

### 13.6 E3：环境项（一条公式，别建模大气层）

```
σ_clutter ≈ σ0 · A_cell / cos ψ
A_cell    = R · θ_az · (c·τ/2)          # 距离-方位分辨单元的地面面积
σ0        ≈ 0.003 (−25dB，草地/农田)；城市/林地 ×3~10
```

例子：R=10km、θ_az=0.035、ΔR=15m、ψ=10° → `A_cell ≈ 5300 m²`、`σ_clutter ≈ 16 m²`。
和坦克的 ~20m² 同量级 → **没有 MTI 就是看不见**，这才是真实的地面监视雷达。

所以杂波不是「加个噪声」，而是**和 MTI 凹口配对**：

```
若 |v_r| < v_notch  →  σ_clutter 全额计入 SNR 分母（目标被埋）
若 |v_r| ≥ v_notch  →  σ_clutter 除以 MTI 改善因子 I（20~40dB）
```

`v_notch = f_notch·λ/2`，`f_notch` 典型 100~200Hz → `v_notch ≈ 1.5~3 m/s`。
副产品：**横穿目标（切向速度）会被 MTI 丢**，这比任何「隐身」设定都自然。

其余环境项：

| 项 | 模型 | 备注 |
|---|---|---|
| 大气衰减 | 双程 `2·α·R/1000` dB，X 晴 0.01、X 大雨 0.1、Ka 大雨 1~3 dB/km | 一条乘性项，Ka 波段雨衰直接劝退 |
| 雷达地平线 | `R_h ≈ 4.12(√h_r + √h_t)` km（4/3 地球） | `air_ai._radar_horizon` 已有，直接复用 |
| 地形遮蔽 | 复用 `detection/los.py` DDA（只在候选上跑） | 已有 |
| 多径/绕射 | **不做** | 收益/成本比太差 |

### 13.7 计算管线（谁在什么时候算哪一档）

```
① 粗搜索（每 tick，全 pair，prange）
   FOV 点积门限 → 距离² 门限 → E0 链路预算（σ = armor.rcs 标量）
   → PD 采样 → 写 det 行（粗）
② 精回波（每 tick，仅候选/已跟踪目标，~500 个）
   取 BoxPool 散射体 → 三面 RCS + 遮挡 → E2-lite 或 E2-full
   → E3 杂波/大气 → 覆盖 det 行的 σ / extent / glint / quality
③ 跟踪与分类（Python，1s）
   α-β 或 Kalman 平滑 → id_level 升级 → TwinEngine.observe
```

为什么分两趟：粗搜索决定「有没有」，精回波决定「是什么」。前者 4.2M pair 必须极简，
后者 500 个目标可以随便讲究。

### 13.8 数值自检清单（写完对着这些数看）

| 检查项 | 期望 |
|---|---|
| 距离每 ×4，SNR | −12dB |
| 锁定驻留 10ms→100ms | +10dB → 探测距离 ×1.78 |
| 坦克侧面 vs 正面 RCS | 侧面 ≈ 1.3~2× 正面 |
| 有 MTI / 无 MTI，10km 地面坦克 | 看得见 / 埋在杂波里 |
| 切向 1m/s 目标 | MTI 丢失 |
| 3m 距离分辨下坦克 | 2~3 个距离单元 |
| 炮塔毁伤后 RCS | 掉 20~40% |

### 13.9 回波专属陷阱

1. **绝对相位用 float32** → 4.2e6 rad 下误差 0.4 rad，相干性全错。用相对相位或 float64。
2. **跨 tick 复用相位** → 物理上已去相干（1s 走 667λ），必须每驻留重抽。
3. **对全 pair 跑 E2** → 2048×2048×6 散射体 = 2500 万次，直接把 1s 预算烧穿。
4. **平板 RCS 公式** `4πA²/λ²` → 算出一辆坦克 300 万 m²，除非你想要这个笑话。
5. **杂波当成噪声加** → 杂波必须和 MTI 配对，否则「移动目标可见/静止目标被埋」这条根本出不来。
6. **PD 用硬阈值** → 没有起伏就没有「时隐时现」，也没有分类特征。
7. **把 det 直接写成真值坐标** → 前面 §七 的战争迷雾全部作废；只写 `(R, az, el, v_r)`。
8. **`det_extent` 当真实尺寸** → 它是「距离单元数 × 分辨率」的估计量，有量化误差，
   正好可以当分类置信度的来源。

## 十四、附录：地面杂波专章（2026-11-05 追问）

### 14.1 先分清三件事，它们不是一个问题

| # | 现象 | 物理 | 引擎里的落点 |
|---|---|---|---|
| ① | 杂波抬高噪底 → 看不远 | 地面回波进主瓣 | **SNR 分母加一项**（本章主线） |
| ② | 杂波形成假目标 | 建筑/塔/强散射点、CFAR 剩余 | 假 blip（可选，§14.7） |
| ③ | 杂波遮挡目标 | 地形/建筑挡住视线 | 已有 `detection/los.py`，**不是杂波** |

绝大多数「地面杂波怎么办」的困难，来自把 ③ 当 ① 做——**能见度问题和信噪比问题是两码事**，
混在一起会得到「什么都看不见」的病态结果。

### 14.2 最划算的解析模型：constant-γ + 分辨率单元

```
σ_c  = σ0 · A_c
σ0   = γ · sin ψ                      # constant-γ 模型（一步 sin，够用）
A_c  = R · θ_az · (cτ/2) · sec ψ      # 距离-方位分辨单元在地面的投影
```

两个式子代进去，`sec ψ · sin ψ = tan ψ`，于是：

```
σ_c = γ · R · θ_az · ΔR · tan ψ       # ΔR = cτ/2
```

**没有三角函数之外的任何东西**，而且 `tan ψ = h / x`（h = 雷达与目标的高度差，
x = 水平距离）——几何量现成，连 `atan` 都不用。

物理含义一览：

| 因子 | 含义 | 效果 |
|---|---|---|
| `R` | 单元面积随距离线性涨 | 远距离杂波更重 |
| `θ_az·ΔR` | 方位波束 × 距离分辨率 | 波束越宽、带宽越窄 → 单元越大 |
| `tan ψ` | 掠射角 | 俯视越陡 → 杂波越强；贴地 → 几乎为零 |

⚠️ `sec ψ` 在正下方（ψ→90°）会爆掉，必须截断：

```
A_c = min(R·θ·ΔR·sec ψ,  π·(R·θ/2)²)   # 后者是波束足迹（俯视时由波束而非脉冲限制）
ψ   = clamp(ψ, 0.3°, 60°)
```

### 14.3 两个算例（这两个数就是整套模型的自检）

**① 地面雷达看地面坦克**（天线高 10m，目标 3km，2° 波束，10MHz → ΔR=15m）

```
tan ψ = 10/3000 = 0.0033
σ_c   = 0.01 · 3000 · 0.0349 · 15 · 0.0033 ≈ 0.05 m²      (γ = −20dB，农田)
坦克  σ = 20 m²  →  SCR ≈ +26dB
```

结论：**低掠射角下，地面杂波对车辆目标并不致命**。这是个反直觉但正确的结果——
坦克在地平线上是「立起来」的，杂波只来自它脚下那一小片。

**② 机载雷达俯视低空目标**（载机 3000m，目标 50m 高，水平距 30km）

```
tan ψ = 2950/30000 = 0.098
σ_c   = 0.01 · 30000 · 0.0349 · 15 · 0.098 ≈ 15 m²
飞机  σ = 5 m²   →  SCR ≈ −5dB
```

结论：**俯视才是杂波真正咬人的地方**。同样是 15m 距离单元，斜距拉到 30km 后
单元面积涨到 1.6 万 m²，杂波比目标大 3 倍。MTI 30dB 之后才回到 +25dB。

> 这就是「低空突防」在数值上的来源，不需要任何特殊规则。

### 14.4 关键：杂波抑制是**按目标自身径向速度**判的

这一点最容易做错。很多实现把 MTI 写成「加个噪声」或「乘一个固定改善因子」，
结果要么静止目标永远看不见（没法玩），要么杂波完全没作用（假模型）。

正确的机制：**杂波在零多普勒附近，目标靠自己的多普勒离开杂波脊**。

```
v_r  = |(v_target − v_radar) · LOS|            # 目标自身相对地面的径向速度
ρ(v) = 1 / (1 + (v_notch / max(v_r, ε))²)      # 残留在杂波脊里的比例
σ_c_eff = σ_c · ρ(v_r)                          # 有效杂波
SNR_eff = SNR / (1 + SNR · σ_c_eff / σ)         # 总干扰 = 噪声 + 杂波
```

`v_notch = f_notch·λ/2`，`f_notch ≈ 100~200 Hz` → `v_notch ≈ 1.5~3 m/s`（X 波段）。

行为表（`v_notch = 2 m/s`）：

| 目标 | v_r | ρ | 结果 |
|---|---|---|---|
| 行进坦克 10 m/s | 10 | 0.04 | 杂波基本消失，正常探测 |
| 爬行坦克 3 m/s | 3 | 0.31 | 探测距离缩水，时隐时现 |
| 停车坦克 0 m/s | 0 | 1.0 | **埋进杂波，MTI 雷达看不见** |
| 悬停直升机 | 0 | 1.0 | 同上；但红外/光学看得见 |
| 巡航导弹 250 m/s | 250 | 0.00006 | 完全脱离杂波，看得见 |

**这是本设计里最重要的一个战术机制**：

> 停车 = 对 MTI 雷达隐形，对红外/光学仍然可见。
> 于是「传感器组合」有了真实价值，而不是数值堆叠。

顺带解释了为什么反炮雷达要找炮口闪光（火炮在阵地上是静止的），
为什么武装直升机要悬停射击（悬停时雷达看不到它）。

### 14.5 σ0 从哪来：现有地形材质的 4 行表

`heightfield.py:30` 只有四种材质：`MAT_TERRAIN / MAT_BRIDGE / MAT_BUILDING / MAT_TUNNEL`。
先用这张粗糙但可用的表：

| 材质 | γ (dB) | 备注 |
|---|---|---|
| `MAT_TERRAIN`（默认） | −20 | 农田/草地基准；林地可 −15，裸岩 −10 |
| `MAT_BUILDING` | −3 | 混凝土立面强散射，城市杂波主力 |
| `MAT_BRIDGE` | −8 | 钢结构，强镜面 |
| `MAT_TUNNEL` | **无回波** | 隧道内单位直接被 span 层屏蔽（现成语义） |

**缺口**：heightfield 没有 land-cover 层（林地/城市/水面的面分布），
所以只能拿「目标脚下那一格的材质」当代理。三个可选补法（按成本排）：

1. **不做**：全局 γ = −20dB，只在 `MAT_BUILDING` 附近 ×10（推荐先这么干）；
2. **程序化**：加载期用一层 Perlin/fBm 噪声生成 `landcover` 字节图（林地/农田/城市），
   与现有 `generate_fbm` 同源，成本一次；
3. **真数据**：加一个 `(W,H) uint8` 列材质层进 heightfield，涉及存档/烘焙/渲染，
   不建议为雷达单独做。

### 14.6 主瓣 vs 旁瓣：只做主瓣，旁瓣用一个 floor

| 项 | 模型 | 建议 |
|---|---|---|
| **主瓣杂波** | §14.2 解析式 | ✅ 必做 |
| **旁瓣杂波** | 全地面面积 × 旁瓣增益，实算要遍历所有格 | ❌ 不做；用 `clutter_floor_db` 常数（−60~−40dB，按俯角插值） |
| 雨/箔条 | 体杂波 `σ_v = η·V_cell` | 需要时再加，一行 |

旁瓣杂波的真实作用是「低空目标被地面反射淹没」，用一个 floor 项就能定性复现，
不值得为它建全地面遍历。

### 14.7 假目标（可选，v2）

CFAR 的门限会自动升到杂波之上，所以「杂波多 → 虚警多」在真实系统里是**被抑制**的；
真正的假目标是**离散强散射体**（建筑、水塔、风机）和 DRFM 欺骗。

定性实现（Python 冷路径，不进 Numba）：

```
每雷达每次扫描：
  期望虚警数 λ = Pfa · N_cells · clutter_factor
  n = Poisson(λ)
  在杂波最重的方位/距离上放 n 个 UNKNOWN blip（det_tgt_idx = -1）
```

`det_tgt_idx = -1` 是刻意设计的：**假 blip 没有真值索引**，
孪生里就是一个低置信接触，AI 会被它骗——这正是战争迷雾想要的东西。

### 14.8 和地形系统的接口（本项目独有的便宜事）

| 地形信息 | 用途 | 成本 |
|---|---|---|
| `surface_z(col)` | 目标脚下高度 → 精确 ψ | 一次采样 |
| span `mat` | σ0 表 | 一次查表 |
| span 层 | 桥下/隧道内单位**无回波**（现成语义） | 零 |
| 坡度（高度场梯度） | 修正有效掠射角（朝雷达的坡 → 更陡 → 杂波更多，但也更「剪影」） | 2 次采样，可选 |
| `detection/los.py` DDA | 地形/建筑遮挡 | 已有，只在候选上跑 |

⚠️ **不要在 pair 循环里采样高度场**（缓存不友好、随机访存）。要么在候选阶段做，
要么预烘焙一张每格的 `surface_z` 数组（其实 `Heightfield` 已有连续地面场，可直接用）。

### 14.9 什么时候可以完全不做（务实降级）

按投入排三级，都能自洽：

| 级别 | 内容 | 工作量 | 得到什么 |
|---|---|---|---|
| **L0 不做** | 杂波项恒 0 | 0 | 雷达在地面永远看得见静止目标；游戏性没问题，真实感缺失 |
| **L1 推荐** | §14.2 公式 + §14.4 速度抑制 + 4 行材质表 | ~50 行内核 | 停车隐形、低空突防、城市难探测 |
| **L2 完整** | + 旁瓣 floor + 假目标 + 坡度修正 + 雨衰 | ~200 行 + 配置 | 雷达工程感 |

**建议直接做 L1**。它是「一条公式 + 一次除法」，却一次性买到三个战术机制。

### 14.11 验收数字

| 检查项 | 期望 |
|---|---|
| 地面雷达 3km 看 10m/s 坦克 | 正常探测，SCR > 20dB |
| 同一雷达看停车坦克 | 杂波埋没，PD ≈ 0 |
| 同一雷达看爬行（2m/s）坦克 | 探测距离缩水 30~50%，断续 |
| 机载 3km 看 30km 外 50m 低空目标 | SCR ≈ −5dB，需 MTI 才可见 |
| 机载看同距离 5000m 高空目标 | ψ≈0 → 无杂波，SCR 只由 RCS 决定 |
| 隧道内单位 | 任何雷达都无回波 |
| 城市建筑旁 | 杂波 ×10，视频闪/假 blip |

### 14.12 杂波专属陷阱

1. **把「看不见」归因于杂波** → 先查 LOS。地形遮挡和信噪比是两件事（§14.1）。
2. **MTI 写成固定改善因子** → 静止目标和高速目标被同等对待，机制全丢。
   必须按**目标自身径向速度**判（§14.4）。
3. **忘了 `sec ψ` 的奇点** → 正下方杂波无穷大。要么 clamp，要么用波束足迹取 min。
4. **杂波随距离单调增但忘了单元面积** → `σ_c ∝ R`（单元变大），
   而 `SNR ∝ R⁻⁴`，两者相除得 `SCR ∝ R⁻³`——远距离杂波相对优势**下降**，
   这点和直觉相反，别写反。
5. **在 pair 循环里采样高度场/查材质** → 随机访存拖垮缓存。候选阶段再做。
6. **每雷达一张杂波图** → 2048 张极坐标图 = 内存灾难；解析式不需要图。
7. **`σ0` 用常数不看掠射角** → 贴地目标被无端埋掉，飞机俯视又不够狠。
8. **假 blip 给了真值索引** → 孪生和 AI 立刻识破，战争迷雾白做（§14.7）。
